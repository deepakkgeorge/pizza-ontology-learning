# Named Graph Strategy

The gene KG uses stable operational graph IRIs under `http://example.org/graph/`.
These graph names are independent of the biomedical ontology namespace
`https://example.org/biomed/ontology#`, which is used for classes, properties, and
instances.

| Graph | IRI | Source | Load policy |
| --- | --- | --- | --- |
| Ontology | `http://example.org/graph/ontology` | `Ontology/gene-practice.owl` | Upload only when the file SHA-256 changes. If changed, delete and replace the graph. |
| Instances | `http://example.org/graph/instances` | `output/kg.ttl` | Delete and replace on every pipeline run. |
| SHACL | `http://example.org/graph/shacl` | `shacl/shapes.ttl`, `shacl/named-graph-shapes.ttl` | Replace when the loader runs, unless `--skip-shacl-upload` is used. |
| Pipeline metadata | `http://example.org/graph/metadata` | Generated by loader | Stores graph role, source path, SHA-256, upload time, and verified triple count. |

The ontology-change decision is based on the SHA-256 hash stored in the metadata
graph for `http://example.org/graph/ontology`. If the stored hash matches the
local `Ontology/gene-practice.owl` hash, the ontology upload is skipped. If the
hash is absent or different, the ontology graph is deleted and uploaded again.

The instance graph is not appended. It is deleted first and then loaded from the
latest `output/kg.ttl`, so each run represents the current materialized KG.

The named-graph metadata policy is described in `shacl/named-graph-shapes.ttl`.
The biomedical entity data validation shapes remain in `shacl/shapes.ttl`. The
loader combines both files into the SHACL named graph.
